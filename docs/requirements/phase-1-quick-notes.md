# Dayflow 第一阶段技术产品需求说明书：基础随手记

版本：v1.0 · 定稿日期：2026-10-03 · 状态：已定稿，作为第一阶段研发基线

本文是第一阶段的技术产品需求说明书，统一定义产品范围、页面与窗口交互、数据结构、输入行为及开发分工。用户已确认本稿定稿，后续开发以本文为基线；人工检查与测试由用户负责，Codex 不编写或执行测试。本文定稿不代表业务功能已实现。2026-10-03 根据最新要求移除草稿缓存功能。

## 1. 产品目标

用户在一天中随手留下简短记录，回顾时能按时间找到当天发生过的事情，减少“忙了一天却想不起做了什么”的情况。

第一阶段建立完整闭环：**写下一条 → 可靠保存 → 当天查看 → 历史回顾 → 修正记录**。

记录可以是完成的工作、沟通、进展、问题、想法或生活片段，不要求用户先整理成文章、任务或日报。产品只能帮助回忆用户主动记录的事情，不保证覆盖一天中的全部活动。

长期定位是统一日志（log）：手动随手记，以及未来 todo、日程、APP 使用监测等模块产生的事件，都可以成为其中的一条日志。第一阶段只实现手动随手记，通过 `type` 为未来日志接入建立基础。

AI 能力不属于本文范围，不定义 AI 交互、接口或研发任务。

### 成功标准

- 从主界面直接输入内容，无需填写标题、分类或项目。
- 提交一条有效记录后，用户明确知道是否保存成功。
- 保存成功的内容在关闭、重启应用后仍可找到。
- 用户能查看今天和任意历史日期的记录，并辨认事情发生的顺序。
- 用户能补记、修改和删除记录，不因操作失败丢失原内容。

## 2. 目标用户与场景

首批面向希望回顾每天工作与生活的个人用户。基于现有 Electron 项目，平台规划以 macOS 为优先，第一阶段仅支持纯文本，全部操作在应用主窗口内完成。第一阶段采用桌面单机模式，无需注册或登录。

| 场景           | 用户行为                                   | 预期结果                             |
| -------------- | ------------------------------------------ | ------------------------------------ |
| 刚完成一件事   | 输入“完成登录流程联调，等待接口验收”并保存 | 自动附带当前时间，出现在今天的记录中 |
| 沟通后记要点   | 输入多行内容，记录讨论结果和遗留问题       | 保留换行，无需组织成正式文档         |
| 临时记一个想法 | 输入一句话并保存                           | 不需要指定类型或归属                 |
| 晚上回顾       | 打开今天的记录，从早到晚阅读               | 看到时间及完整内容                   |
| 次日补记       | 选择昨天，设置事情发生的时间并记录         | 内容归入昨天，而非今天               |
| 修正或清理     | 编辑正文、调整时间或删除误记               | 时间线正确更新，操作有明确反馈       |

- 独立的日报编辑、模板和发布流程。

## 4. 核心概念与时间规则

### 4.1 统一日志与类型

**一条记录**是统一日志中的一个条目，具有稳定标识、日志类型 `type`、正文和记录时间。当前“随手记”特指用户手动发送的日志。

`type` 表示日志来自哪类记录能力，不是用户自由填写的内容分类，也不等同于未来标签。一条手动记录即使正文写着“完成待办”或“下午开会”，仍是 `manual`；不能根据正文将其改为其他模块日志。

本次确定以下类型标识，标识在存储与接口中保持稳定，不随界面语言变化：

| type       | 中文名称 | 英文名称     | 含义                             | 本版范围                               |
| ---------- | -------- | ------------ | -------------------------------- | -------------------------------------- |
| `manual`   | 随手记   | Note         | 用户在随手记输入区主动发送的内容 | 实现创建、读取、编辑与回收站操作       |
| `todo`     | 待办日志 | Todo log     | 未来 todo 模块产生的日志         | 仅确定类型，不实现模块、事件生成或接入 |
| `schedule` | 日程日志 | Schedule log | 未来日程模块产生的日志           | 仅确定类型，不实现模块、事件生成或接入 |

- 每条日志有且仅有一个非空 `type`，创建后不通过正文编辑或时间调整改变。
- 手动输入入口由系统赋值 `manual`，不增加类型必选项，也不允许用户从此入口伪造 todo 或日程日志。
- 将来 todo、日程中的具体事件（例如创建、完成、变更）与关联对象如何表达，由各模块需求定义；不在本版增加事件子类型。
- 后续新增模块可增加新的稳定类型；既有类型的语义不重新解释。APP 使用监测的类型待相关模块需求确定。
- 未来模块对象与日志记录是不同概念：本篇不定义删除或恢复日志是否影响原模块对象，也不将两者默认联动。

### 4.2 三个时间字段

每条日志只定义三个时间字段，将此前独立的发送时间与发生时间合并为 recordedAt：

| 字段         | 含义             | 赋值与编辑规则                                                       |
| ------------ | ---------------- | -------------------------------------------------------------------- |
| `createdAt`  | 系统真实创建时间 | 数据服务在首次成功创建时自动赋值，不允许用户传入或修改               |
| `updatedAt`  | 系统真实更新时间 | 创建时等于 createdAt；每次实际保存修改时由系统更新，不允许用户自定义 |
| `recordedAt` | 记录时间         | 发送时可使用当前时间或自定义时间；编辑时在同一字段中修改并保存       |

`recordedAt` 是界面展示、日期归属与列表排序的唯一业务时间。`createdAt` 和 `updatedAt` 反映真实系统操作，不因为用户补记或调整记录时间而回填为过去时间。

编辑规则：编辑界面载入原记录时间，用户可以修改；只改正文而未调整时间时保留 recordedAt，系统仅自动更新 updatedAt。若用户在编辑时选择“当前时间”，则 recordedAt 更新为本次保存修改时刻。此规则将“编辑的记录时间”保存在同一业务字段中，不增加第四个日志时间字段，也不记录历史时间版本。

1. 新建选择“当前时间”时，recordedAt 在点击发送时取值；选择自定义时使用用户指定值。同一次失败重试保持相同 ID 与 recordedAt。
2. 历史日期补记使用自定义日期与时间。修改 recordedAt 后重新计算归属日期、重新排序；跨日时移到新日期。
3. 每日列表按 recordedAt 从早到晚排列；相同时按 createdAt、稳定 ID 排序。打开列表仍自动滚动到底部。
4. localDate 按 recordedAt 与 timeZone 计算。每天为本地自然日 00:00 至次日 00:00 之前；系统时区变更不自动重分旧记录日期。
5. 不允许未来记录时间；新建与编辑使用相同校验。未来日期可浏览，但不提供未来记录新建。
6. 跨午夜不自动切换查看日期或草稿目标日期；原目标已为历史日期时，须指定或确认 recordedAt。
7. 未来模块日志也使用 recordedAt 表达其业务记录时间，具体赋值由模块另行定义；不得通过模块接入覆盖系统 createdAt/updatedAt。

## 5. 功能需求与人工检查参考

### FR-01 新建记录

- 主界面提供常驻多行输入区域，正文是唯一必填内容；历史补记另外要求时间。创建的日志自动设置为 `manual`，包括补记。
- 正文上限为 10,000 个 Unicode 字符（已确认）；仅含空白的内容不可保存。
- 保留有效正文的换行、缩进和原始文本，不自动改写；去除首尾空白仅用于判断是否为空。
- Enter 换行；Cmd+Enter（macOS）或 Ctrl+Enter（Windows/Linux）提交；中文输入法正在组字时不触发提交。
- 保存过程中禁用重复提交；一次提交意图最多产生一条记录，包括失败后重试。
- 只有持久化成功后才清空输入和草稿，并将新记录显示在列表中；失败保留输入，提供重试入口。

**人工检查参考**：两行中文保存后完整显示；连续提交不生成重复条目；断开网络仍可保存；模拟写入失败后正文和指定时间仍保留。

### FR-02 当日与历史回顾

- 启动默认查看今天，显示日期、记录总数和按记录时间升序排列的列表；当日或历史列表加载完成后自动滚动到底部，向上滚动阅读记录时间更早的内容。
- 每条记录至少展示记录时间、类型与正文；长内容可展开，必须能阅读全文。
- 支持前一天、后一天、选择日期及返回今天；历史日期没有记录时也能查看和补记。
- 切换日期只读取所选日期的未删除记录，不把其他日期或回收站中的记录混入列表；当天条目数也排除软删除记录。
- 加载、空列表、读取失败为不同状态；读取失败不得显示“这一天没有记录”。
- 新建成功后确保新条目可见；其他更新不自动滚动打断用户正在进行的阅读。

**人工检查参考**：两天的记录按日期隔离；空日期显示明确空状态；相同记录时间的条目多次打开顺序一致；读取失败可以重试。

### FR-03 补记和编辑

- 在历史日期新建记录，保存前可见目标日期及指定时间。
- 本版 `manual` 记录支持修改正文与 recordedAt 的日期及时间，`type`、createdAt、updatedAt 不可手动编辑，沿用新建时的校验；仅编辑正文保留 recordedAt；调整记录时间后更新同一字段，并改变排序及必要的日期归属。
- 编辑成功后更新列表，创建时间保持不变；取消不修改已保存记录。
- 编辑失败保留编辑内容和原记录。
- 有未提交修改时，取消编辑、切换日期或正常关闭窗口须提供保存、放弃或继续编辑的选择；保存失败不能继续关闭并丢弃内容。
- 未保存的新建输入与编辑修改在关闭后不恢复，原记录仍须完整。

**人工检查参考**：补记昨天 14:30 的事情后出现在昨天；跨日编辑后，两天列表与计数正确更新；取消及写入失败不改变原记录。

### FR-04 回收站与删除

- 每日列表的删除只将记录移入回收站（软删除），保留正文、类型、recordedAt、归属日期、唯一标识及 createdAt。
- 移入成功后从每日列表隐藏并更新数量；失败时保持原状态，不显示成功。
- 回收站在主窗口内展示所有日期的已删除记录，按移入时间倒序排列，相同时间按稳定唯一标识排序。
- 回收站允许阅读全文、恢复和彻底删除；不直接编辑记录，需先恢复。
- 恢复将记录放回原归属日期、按原记录时间排序，保留原唯一标识、记录时间和创建时间，不复制生成新记录。
- 只有已在回收站的记录才能彻底删除；再次确认后删除数据库中的该记录。正常记录不提供直接彻底删除的入口或操作权限。
- 第一版不做自动过期清理、批量操作或“清空回收站”。记录保持在回收站，直到用户恢复或明确彻底删除。
- 恢复和彻底删除失败时保留回收站原条目，提供重试；操作期间禁止重复执行。

**人工检查参考**：移入后在每日列表消失但重启后仍可在回收站找到；恢复后回到原日期且仅有一条；取消彻底删除保留记录，确认后重启也不可恢复；模拟各操作失败时原状态完整；正常记录不能通过绕过界面的请求被直接彻底删除。

### FR-05 未提交输入

- 新建输入仅保留在当前窗口内，不持久化，关闭窗口后不恢复。
- 切换日期、回收站或设置不清空输入，不静默改变目标日期；未提交输入不计入正式日志条数。
- 正式提交成功后清空输入；SQLite 写入失败保留内容，并使用同一提交 ID 重试。

**人工检查参考**：切换视图保留当前输入；关闭后重新打开输入为空；失败重试不生成重复日志。

### FR-06 本地存储与可靠性

- 使用 SQLite 保存正式日志、应用偏好与迁移版本；未提交输入仅存内存，数据库不设草稿表。
- 数据保存在应用的持久用户数据目录，不依赖开发目录、构建产物或网络。
- 正文按纯文本处理，输入 HTML 或脚本时不执行。
- 保存成功以持久化写入完成为准；记录写入成功后清空输入，并按提交 ID 去重，避免失败重试重复提交。
- 写入失败、磁盘空间不足、文件不可读等异常给出可理解的提示，不虚报成功。
- 数据不可读时不得静默覆盖为空库；保留原文件并提供重试入口。
- P0 限制为单应用实例，避免并发修改记录。
- 应用版本更新后继续读取既有记录；存储结构需有版本信息，为后续迁移提供依据。
- 第一阶段不主动上传记录；暂不增加应用级加密。P0 未包含备份恢复，无法保证磁盘损坏后的恢复。

**人工检查参考**：增删改后退出、重启结果一致；模拟写入及读取错误时原数据不会被清空；含脚本文本的记录以文字显示。

### FR-07 日夜主题与跟随系统

- 支持“浅色 / Light”“深色 / Dark”“跟随系统 / System”三种模式，用户可在主窗口内设置。
- 首次启动默认“跟随系统”（已确认）。跟随系统时按 macOS 当前外观显示，并在系统外观变化时即时更新，无需重启。
- 手动选择浅色或深色后，应用固定使用该模式，系统外观变化不覆盖用户选择；重新选择跟随系统后立即应用系统当前外观。
- 切换即时生效，覆盖每日记录、回收站、设置、菜单、日历、确认框、输入、加载与失败状态；应用可控制的窗口背景与标题栏外观协调一致。
- 切换不重载业务页面，不清空草稿或编辑内容，不改变所选日期、滚动位置或对话框状态。
- 持久化保存用户选择的模式，不把系统当前解析出的浅色或深色替代“跟随系统”偏好；重启先应用偏好，避免明显的错误主题闪烁。
- 无法读取系统外观时回退浅色，并保留跟随系统模式；后续获得系统状态后恢复跟随。
- 两种主题均需保证正文、次级文字、边框、焦点、禁用态与危险操作可辨认，不以颜色作为唯一提示。

**人工检查参考**：三种模式即时切换；跟随系统时系统变更会同步更新，手动模式不被覆盖；重启保留选择；在编辑、回收站和删除确认框中切换不丢内容，所有区域使用一致主题。

### FR-08 多语言与新增语言能力

- 第一版支持英文（`en`）与简体中文（`zh-CN`）；设置选项始终使用各语言自身名称“English”和“简体中文”，方便用户识别并切回。
- 首次启动按系统首选语言列表匹配（已确认）：支持的英文地区变体映射至 `en`，简体中文及其兼容地区变体映射至 `zh-CN`；其他语言不自动视为简体中文，未匹配时回退英文。
- 用户手动选择后保存语言偏好，后续启动优先使用该选择，系统语言变化不覆盖它。本版不额外提供持续“跟随系统语言”的选项；未手动选择时启动按系统语言匹配。
- 切换即时生效，无需重启；不清空输入、草稿或编辑内容，不关闭当前对话框，不改变查看日期及业务状态。
- 覆盖全部应用自有界面文案：主窗口、回收站、设置、日期选择、菜单、按钮、提示、验证错误、空状态、确认框、可访问名称及应用自定义菜单。系统原生控件的文案遵循系统行为。
- 用户正文和草稿保持原样，不翻译、不改写；产品名称 Dayflow 与数据中的稳定标识不随语言变化。
- 日期、星期和条目计数按当前界面语言展示；仍保持第 6 节约定的 24 小时制。语言切换只改变显示，不改变时间值、时区、归属日期或排序。
- 文案以稳定语义键和独立语言资源维护，支持参数插值与语言相应的数量表达，不通过拼接固定中文或英文句子生成提示。
- 统一维护语言注册信息、资源加载与回退规则。新增语言应能通过新增资源及注册信息接入，不修改记录业务逻辑、存储字段或复制页面。
- 英文作为缺失文案的回退语言，运行时不直接展示资源键、空字符串或 `undefined`；两种已支持语言的资源应完整，避免用回退掩盖漏译。
- 第一版支持当前两种语言；后续从右向左语言若加入，需额外适配方向和布局，不承诺本版完成该适配。

**人工检查参考**：英文与简体中文均能完成新建、补记、编辑、回收站操作和设置；切换及重启保留手动选择；不支持的系统语言回退英文；正文与时间归属不变；英文长文案在最小窗口下不遮挡按钮；模拟缺失资源时使用英文回退；新增语言仅需增加资源与注册信息，不需修改业务逻辑。

### FR-09 日志类型与扩展边界

- SQLite 存储与读取返回的数据均须包含 `type`；本版新建与补记固定写入 `manual`，编辑、软删除、恢复不改变该值。
- 如升级时已有历史手动记录缺少 `type`，通过存储迁移补为 `manual`；这是旧数据迁移规则，不是未知类型的通用回退。
- 每日列表及回收站采用统一日志数据定义，按日期和删除状态查询，不将查询结构固定为仅查询 `manual`。
- 本版不产生 `todo` 或 `schedule` 数据，不创建虚拟条目，不增加类型筛选或外部模块写入接口。
- 日志展示与类型定义分离，类型名称通过语言资源映射；遇到尚未支持的类型时保留原始标识，显示“其他日志 / Other log”，不误标为手动记录，不提供手动编辑入口。
- 未来模块日志的结构化数据、来源对象关联、事件去重与可执行操作另行设计；本版只预留扩展边界，不实现通用事件总线或模块同步机制。

**人工检查参考**：普通输入、补记和草稿提交均保存为 `manual`；修改内容、时间及回收站恢复后类型不变；界面不能选择或伪造未来模块类型；日志类型不随中英文切换改变。

### FR-10 设置页与扩展框架

- 在现有主窗口内提供独立设置页，通过页面切换进入，不采用设置对话框，也不另开系统窗口。
- 设置页采用左侧模块菜单、右侧配置内容的布局；菜单切换只改变右侧模块内容，页面框架保持稳定。
- 第一版菜单提供“常规 / General”和“外观 / Appearance”：语言位于常规模块，主题位于外观模块。
- 后续新增模块、分组或设置项应复用菜单、内容标题、分组容器、配置行与状态反馈结构，不为每个模块重新设计页面。
- 本版不提前展示 todo、日程、监测、账号、搜索等未实现模块的菜单或空配置页。
- 进入、模块切换及返回不能丢失随手记草稿；有未保存的日志编辑时先遵循已有离开保护。

**人工检查参考**：可从每日记录及回收站进入设置，菜单点击后显示对应配置；返回时保留原视图与日期及草稿，每日列表重新打开时定位底部；主题与语言偏好仍即时应用并持久化。

### FR-11 自定义窗口顶部与边缘

- 不采用独立、明显分割的 Electron 默认窗体标题栏框。应用自行设计顶部背景、导航、标题、分隔与窗口内侧边缘，内容可以延伸至顶部和窗口内侧边界。
- 窗口顶部与业务内容整合为统一外观：每日记录的日期与操作、回收站标题与返回、设置页导航与标题可进入顶部区域，不再叠加一条仅显示 Dayflow 的默认标题栏。
- 主窗口仍需支持关闭、最小化、缩放/全屏、移动和边缘调整大小；自定义外观不取消这些操作，也不绕过未保存编辑的关闭保护。
- macOS 第一版保留原生红黄绿窗口按钮，并由应用设计按钮位置、留白和周围内容；不要求重绘原生按钮。若后续决定自绘，另行补充按钮外观与全部系统行为。
- 顶部空白区域可拖动窗口，业务按钮、输入、菜单和可选择正文不可被拖动区域覆盖。
- 窗口顶部、内侧边缘与内容背景随主题统一变化；浅色和深色均不出现独立默认标题栏色块。

**人工检查参考**：顶部与页面融合，按钮可点击、空白可拖动；窗口可调整大小和全屏；最小窗口下业务内容不覆盖红黄绿按钮；关闭仍遵循既有编辑与草稿规则。

## 6. 第一版页面与主窗口界面需求

本节定义第一版采用的界面方案。以“打开就能记录，同时看到当天做了什么”为设计目标。正式功能集中在一个主窗口：每日记录视图上方切换日期，中间阅读记录，下方持续提供输入入口；回收站和设置页通过主窗口内的页面切换访问，复用同一窗口。

### 6.1 页面边界与布局

- 首页命名为“每日记录”，启动显示今天；首页不设仪表盘、侧边栏或独立记录详情页。设置为独立页面，拥有自己的左侧模块菜单；首页、回收站、设置均位于同一主窗口。
- 首页采用单列布局，自定义顶部与窗口内侧边缘；日期导航融入顶部，原生窗口按钮留出专用区域。业务背景可延伸到边缘，正文仍保留阅读内边距。
- 初始窗口为 900 × 670，最小为 760 × 560（逻辑像素）；窗口可调整大小。这些尺寸作为首版布局基线，视觉细节可在实现中细化。
- 日期导航固定在内容顶部；记录列表独立纵向滚动；新建输入区域固定在底部，不随列表滚走。
- 内容区域居中，最大宽度 880；较窄窗口自动收缩，正文换行，不出现页面横向滚动。
- 输入区域正文初始约三行，随输入增长，整体最多占工作区高度的 35%；超过后正文区域内部滚动，保存按钮始终可见。

结构示意（用于约定区域与信息顺序，不代表最终视觉稿）：

```text
┌──────────────────────────────────────────────────────┐
│ ● ● ●  ‹ 2026年10月2日 › [今天] 共3条 [回收站] [设置] │
├──────────────────────────────────────────────────────┤
│ 09:20  完成登录流程联调                         [···] │
│        等待接口验收                                  │
│                                                      │
│ 11:00  与产品讨论交互细节                       [···] │
│                                                      │
│ 15:30  修复测试环境问题                         [···] │
│                                   记录列表可独立滚动 │
├──────────────────────────────────────────────────────┤
│ 记录到 2026-10-02 · 今天     时间：当前时间 [调整]       │
│ ┌──────────────────────────────────────────────────┐ │
│ │ 记下刚刚做了什么，或此刻的想法……                  │ │
│ └──────────────────────────────────────────────────┘ │
│                                             [记录]   │
└──────────────────────────────────────────────────────┘
```

条目数仅代表当前所选日期已保存且未删除的记录数量，不包含草稿或回收站中的记录，也不显示为任务完成数量。

### 6.2 顶部日期导航与回收站入口

| 元素            | 界面要求                                 | 操作行为                                                     |
| --------------- | ---------------------------------------- | ------------------------------------------------------------ |
| 当前日期        | 展示年、月、日和星期；今天追加“今天”标识 | 点击日期打开日期选择浮层                                     |
| 前一天 / 后一天 | 左右箭头，提供明确可访问名称             | 按自然日切换，不跳过无记录的日期                             |
| 今天            | 固定可见，查看今天时禁用                 | 返回当前系统日期                                             |
| 日期选择浮层    | 月份导航、日历网格、选中日期和今天标识   | 选中日期后关闭；取消不改变日期                               |
| 条目数          | 当前日期的正式记录数量                   | 加载时显示占位，读取失败时显示“数量不可用”，不显示误导性的 0 |

每日记录视图顶部另外提供常驻“回收站”文字入口，进入后在同一窗口展示回收站；不打开独立窗口。

选择未来日期遵循第 4 节规则：允许浏览，列表提示“这一天尚未到来”，新建区域不提供未来记录提交。已有其他日期草稿仍允许继续处理。

启动、切换日期或从设置/回收站返回每日列表时，加载完成后均滚动至底部，看到该日最新发送的内容；向上滚动查看更早内容。不恢复每日列表上次的阅读位置。

### 6.3 中间记录列表

- 按记录时间从早到晚展示，每条左侧显示 recordedAt 对应的记录时间，采用 24 小时制（HH:mm），右侧展示类型名称、正文与更多操作入口。类型名称作为轻量说明，本版实际条目均显示“随手记 / Note”。
- 正文保持换行，长单词和链接可折行；链接以纯文本显示，第一版不增加链接预览或富文本渲染。
- 正文超过六个显示行时折叠，提供“展开全文”和“收起”；编辑时载入完整正文。
- 本版手动日志的更多操作菜单只有“编辑”和“移入回收站”；菜单按钮可通过键盘到达，不依赖鼠标悬停才能发现。
- 默认不展示创建时间、更新时间、标签、头像、任务勾选、统计图表等信息。
- 成功新建记录后让该条可见，并将焦点回到输入框；补记按自定义 recordedAt 插入对应位置，成功后定位该条；再次打开列表时仍定位底部。
- 用户阅读旧记录时，后台变化不改变列表滚动位置。

### 6.4 底部新建输入区

| 元素       | 界面要求                                                         | 操作行为                                                           |
| ---------- | ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| 日期与时间 | 发送框左下角以胶囊显示日期和时间；默认使用当前时间               | 点击打开包含日历和时间的复合选择框，一次确认生效；支持切回当前时间 |
| 正文输入框 | 多行纯文本，有可访问标签，提示“记下刚刚做了什么，或此刻的想法……” | Enter 换行；粘贴仅保留文本                                         |
| 主按钮     | 今天显示“记录”，历史日期显示“补记”；提交中显示“保存中…”          | 点击提交；空白、超长、时间不合法或保存中时不可重复提交             |

- 输入区域固定产生手动日志，不提供类型选择；不增加标题、用户自定义分类、标签、附件或格式工具栏。
- 字数接近上限或超限时才显示计数及提示；正文、时间校验提示出现在对应控件附近。
- 无输入时，顶部切换日期同步更新新建目标日期；有输入时保留原目标日期。记录日期与时间仅通过发送框左下角的胶囊展示和调整。
- 启动默认查看今天，新建输入为空。
- 草稿目标日期与查看日期不同时，正式保存成功后切换到目标日期并定位新条目；不能仅在当前日期列表里显示成功消息而让用户找不到记录。
- 跨午夜不静默改变草稿目标日期；原日期已成为历史日期时，要求填写或确认记录时间后再补记。
- 应用启动且可以输入时，默认聚焦正文输入框；数据初始化完成前不允许提交。

### 6.5 编辑与删除交互

**编辑采用记录条目内展开的方式**，不把已保存记录载入底部的新建输入区，避免覆盖新建草稿。

- 点击“编辑”后，该条目展示完整正文输入、recordedAt 的日期与时间、“使用当前时间”、“保存修改”和“取消”；系统 createdAt/updatedAt 不作为可编辑控件。
- 同一时间只编辑一条记录。编辑期间底部新建区保留草稿，但暂时不可操作；进入另一条编辑须先完成或取消当前编辑。
- 日期导航保持可见；有未保存修改时，离开当前编辑需要选择保存、放弃或继续编辑。无修改时直接退出编辑并切换。
- 保存中禁止重复保存；失败在该条目内提示并保留编辑内容；成功恢复阅读态。
- 修改时间后在当前日期内重新排序并定位该条；跨日修改成功后留在原查看日期，原条目移出列表；显示“记录已移至 YYYY-MM-DD”及“查看该日”入口。
- 进入编辑时聚焦正文；取消后焦点回到该条目的更多操作按钮。

**移入回收站采用确认对话框**：标题“移入回收站？”，展示发生日期、时间和正文摘要，说明“可以在回收站恢复”；按钮为“取消”和“移入回收站”。失败保留原记录和对话框；成功关闭、更新每日数量，并提示“已移入回收站”，提供“查看回收站”入口。

**回收站视图**：

- 顶部展示“回收站”、已删除条目数与“返回每日记录”；不使用每日日期筛选。
- 每条记录展示类型名称、原记录日期与时间、正文以及移入回收站的时间，支持展开全文；操作只有“恢复”和“彻底删除”。
- 进入时保留每日视图的日期和新建草稿；回收站隐藏新建输入区和日期导航，不创建或修改记录。
- 进入时若存在未保存编辑，沿用保存、放弃或继续编辑的离开保护。
- 点击“返回每日记录”回到进入前的日期，加载后定位每日列表底部，恢复新建输入区；草稿原样保留。
- 恢复成功后条目从回收站移除，显示“已恢复到 YYYY-MM-DD”与“查看该日”；不强制离开回收站。查看该日则进入对应每日列表并定位恢复的记录。
- 彻底删除必须再次确认：标题“彻底删除这条记录？”，展示时间与摘要，说明“此操作无法恢复”；按钮为“取消”和“彻底删除”，默认焦点在取消。
- 回收站为空时显示“回收站为空”，不放示例内容；加载显示占位，读取失败显示“回收站读取失败”和重试，不能显示为空。
- 操作失败在条目或确认框内反馈，保留内容；成功后更新回收站数量及相关每日数量。

### 6.6 页面状态与反馈

| 状态                  | 列表与反馈                                                   | 输入区域                                  |
| --------------------- | ------------------------------------------------------------ | ----------------------------------------- |
| 首次启动 / 今天无记录 | “今天还没有记录”，辅助说明“从下面记下一件事开始”             | 正常可用，无示例假数据                    |
| 历史日期无记录        | “这一天还没有记录”，提示可在下方补记                         | 目标为该日，要求填写记录时间              |
| 未来日期              | “这一天尚未到来”                                             | 无草稿时不提供新建；保留其他日期已有草稿  |
| 日期记录加载中        | 列表显示加载占位，不继续展示上一个日期的条目                 | 保留现有草稿，不抢焦点                    |
| 日期记录读取失败      | “记录读取失败”及“重试”，不伪装为空列表                       | 保留输入；是否可提交取决于存储服务可用性  |
| 数据库初始化失败      | 明确显示“无法打开本地记录”与“重试”，不自动创建空库覆盖原数据 | 禁用提交，不清空已在内存中的输入          |
| 正式保存中            | 不提前插入成功条目                                           | 主按钮显示“保存中…”，暂时锁定本次提交内容 |
| 正式保存失败          | 不插入未保存条目                                             | 正文和时间保留，就近显示原因与重试入口    |
| 正式保存成功          | 新条目可见，数量更新，短暂提示“已记录”                       | 清空已提交草稿，准备下一条                |

成功提示可短暂消失；失败提示须保留到重试成功或用户明确处理。反馈使用用户能理解的语言，不展示 SQL、文件堆栈或 IPC 名称。

### 6.7 设置页布局、导航与配置规范

#### 页面样式与结构

以用户提供的 Codex 设置截图作为布局参考：左侧固定模块菜单，右侧宽配置区；右侧以模块标题、分组标题、配置容器和配置行组织内容。参考图中的权限、通知、导入、集成等具体项目不属于 Dayflow 本版功能。

- 每日记录与回收站顶部均保留“设置”入口；进入后主窗口工作区完整切换为设置页，不叠加遮罩或弹窗。
- 设置页沿用自定义窗口框架：窗口按钮、返回和设置标题可进入顶部，左侧菜单背景延伸至顶部及左侧内边缘；不保留额外默认标题栏。设置页不显示日期导航、每日列表或新建输入区。
- 左侧菜单宽度基线为 200 个逻辑像素，包含“返回”入口、“设置 / Settings”标题、菜单分组名称和模块列表。
- 右侧占据其余可用宽度，显示所选模块标题和分组配置；配置内容最大宽度基线为 800，周围留出阅读空间。
- 菜单和右侧内容各自纵向滚动；内容较长时右侧滚动不使菜单消失。最小窗口下保持双栏，不出现整页横向滚动。
- 当前菜单项通过背景、文字与选中语义明确标识；图标为辅助，不替代模块名称。
- 配置行通常左侧为名称及简短说明，右侧为控件；窗口较窄或文案过长时控件可移到该行下方，名称和说明不得遮挡。
- 使用分组标题与轻量容器归并相关设置，容器内配置行用分隔线区分；整体遵循应用浅色与深色主题。

#### 进入、切换与返回

- 本次应用会话首次进入设置默认选中常规；再次进入可恢复本会话最后选中的模块。不要求跨重启保存设置页位置，重启仍默认进入每日记录首页。
- 点击左侧菜单立即替换右侧内容并从该模块顶部开始，不关闭主窗口；主题或语言切换不重置当前模块、内容滚动或操作状态。
- 设置页左侧“返回”回到进入前的每日记录或回收站视图，保留日期；返回每日列表时定位底部，返回回收站时保留其阅读位置，焦点回到原设置入口。
- 未提交新建内容在进入设置后继续保留为草稿，不因页面隐藏清空；从设置返回再显示原目标日期与正文。
- 若当前正在编辑日志且有未保存修改，进入设置前提示保存、放弃或继续编辑；保存失败不离开原编辑。没有修改则正常退出编辑后进入设置。
- Escape 用于关闭设置页中打开的下拉菜单或对话框，不作为关闭设置页的默认动作；返回由明确的返回入口完成。

#### 设置项交互与状态

- 当前主题与语言选择即时应用并保存，不提供页面级“保存”按钮；返回不撤销已生效的选择。
- 每个配置项有稳定名称、可选说明、控件和就近状态反馈。配置项使用稳定 ID 与设置键，不通过当前语言的显示文案识别。
- 初次读取偏好时展示加载状态；可确认当前值前禁用对应控件，避免误覆盖已保存设置。读取失败按第 7.3 节规则回退并提示。
- 偏好写入中显示保存状态；失败保留当前会话效果，明确提示“设置未保存，重启后可能恢复原设置”，提供重试，不虚报已保存。
- 连续调整同一设置时以最后一次选择为准，不能因旧请求晚返回覆盖新选择；各项反馈不互相覆盖。
- 切换语言后，设置页标题、菜单、分组、说明、控件和反馈同步更新，选中模块仍通过稳定 ID 保持。

#### 后续扩展约定

- 模块注册信息包含稳定模块 ID、所属菜单分组、显示顺序、名称的语言资源键及右侧配置内容入口；模块 ID 不随重命名或语言切换变化。
- 模块内配置以分组组织，每个配置项有自己的设置键、默认值、值校验及持久化规则；复用主题与语言已有的偏好服务和反馈方式。
- 新增模块只需增加对应模块内容、注册信息及语言资源，不修改首页日志逻辑或复制整套设置布局。
- 未实现模块不注册为用户可访问菜单；本版只实现两个已有模块，不开发动态插件加载或通用可视化配置引擎。
- 未来需要提交确认或产生额外副作用的设置，另行定义保存与离开保护；本版主题、语言的即时保存规则不强制套用到所有未来设置项。

### 6.8 通用窗口框架与顶部布局

首页、回收站和设置页复用同一窗口框架，配置各自顶部内容，不为每个页面复制窗体控制实现。

| 区域         | 首版界面约定                                                          |
| ------------ | --------------------------------------------------------------------- |
| 窗口按钮区   | 顶部左侧为 macOS 红黄绿按钮预留空间；实际位置与安全留白随窗口状态调整 |
| 每日记录顶部 | 日期、前后日、返回今天、条数、回收站和设置入口与窗口顶部融合          |
| 回收站顶部   | 返回、回收站标题、数量及设置入口与窗口顶部融合                        |
| 设置页顶部   | 返回与设置标题进入顶部；左侧菜单和右侧模块区域保持双栏                |
| 拖动区       | 顶部背景及明确空白区域，不包含交互控件；始终保留可抓取的拖动空间      |
| 窗口内侧边缘 | 背景和菜单可贴边；正文、输入和控件有必要留白，不与系统缩放边缘冲突    |

- 在最小窗口、全屏、退出全屏及窗口非激活状态下，重新布局可用区域，确保控件不被系统按钮遮挡，也不产生重复窗口按钮。
- 顶部布局需适配中英文长度；缩小时可让日期与次级信息分行，窗口控制区、主要导航及拖动区不能消失。
- 编辑和文本区域支持正常点击与选择；拖动窗口不能误触发发送、返回、删除或日期切换。
- macOS 原生窗口按钮的系统行为由原生窗口承担；关闭操作进入既有数据保护流程。顶部双击等原生交互须保持合理的 macOS 行为，不把双击业务控件当作窗口操作。

技术实现建议：macOS 使用 Electron 自定义标题栏能力，如 `titleBarStyle: 'hidden'` 或 `'hiddenInset'`，配合 `trafficLightPosition` 调整原生按钮位置；页面占用标题栏可用内容区域。拖动背景定义 `app-region: drag`，所有交互控件定义 `app-region: no-drag`。具体参数在研发时结合布局选定，不因此增加窗口设置项。[Electron 自定义标题栏](https://www.electronjs.org/docs/latest/tutorial/custom-title-bar)、[自定义窗口交互](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)。

## 7. 数据库结构与提交设计

本节作为研发的数据约定，列明首版 SQLite 表结构、字段、索引及操作规则。使用单个数据库 `dayflow.sqlite` 保存正式日志与偏好；不包含草稿、标签、搜索索引、todo 对象或日程对象。

- 数据库位于应用持久用户数据目录的独立数据子目录，不放在构建目录或缓存目录。
- 对外字段使用 camelCase，数据库列使用 snake_case，由数据层显式映射。
- 全部绝对时刻使用 UTC Unix 毫秒整数；日期使用 `YYYY-MM-DD`，时区使用 IANA 标识。记录时间显示时使用记录的 `time_zone`，不随系统时区变更漂移。
- UUID 由应用生成，数据库唯一主键负责提交去重；时间不能作为记录唯一标识。

### 7.1 首版 SQLite 表结构

#### logs：统一日志

| 数据库字段  | 接口字段   | 类型    | 约束与含义                                               |
| ----------- | ---------- | ------- | -------------------------------------------------------- |
| id          | id         | TEXT    | 主键，稳定 UUID，同次提交及重试不变                      |
| type        | type       | TEXT    | 必填，本版写入 manual，已定义 todo、schedule             |
| content     | content    | TEXT    | manual 原始纯文本，非空白且最多 10,000 个 Unicode 字符   |
| recorded_at | recordedAt | INTEGER | 必填，用户选择的记录时间；用于日期归属和排序，编辑可调整 |
| time_zone   | timeZone   | TEXT    | 记录时间的时区，用于显示及归属日期计算                   |
| local_date  | localDate  | TEXT    | recorded_at 在 time_zone 下的日期                        |
| created_at  | createdAt  | INTEGER | 必填，系统自动记录真实创建时间，创建后不变               |
| updated_at  | updatedAt  | INTEGER | 必填，系统自动记录最近真实修改时间                       |
| is_deleted  | isDeleted  | INTEGER | 0 正常、1 在回收站，默认 0                               |

```sql
CREATE TABLE logs (
  id TEXT NOT NULL PRIMARY KEY,
  type TEXT NOT NULL CHECK (length(type) > 0),
  content TEXT NOT NULL,
  recorded_at INTEGER NOT NULL,
  time_zone TEXT NOT NULL,
  local_date TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  is_deleted INTEGER NOT NULL DEFAULT 0 CHECK (is_deleted IN (0, 1))
);

CREATE INDEX idx_logs_active_date_recorded
  ON logs (local_date, recorded_at, created_at, id)
  WHERE is_deleted = 0;
```

created_at/updated_at 不由渲染层表单或模块提交值指定，由主进程数据服务在实际数据库创建/修改时自动填入真实时刻。创建二者相等；保存正文、记录时间以及软删除/恢复时更新 updated_at；取消、失败回滚或未发生实际变化的请求不更新时间。仅 recordedAt 可由用户指定，调整时必须同时更新 time_zone/local_date，不允许三个值相互矛盾。

同次提交失败重试保留 id 与 recordedAt，createdAt 仍取实际成功创建的系统时刻。失败后再次修改前先查询原 ID 是否已写入；若已写入则按成功处理，确认未写入后才开始新的提交，避免重复日志。

每日查询使用 `WHERE local_date = ? AND is_deleted = 0 ORDER BY recorded_at ASC, created_at ASC, id ASC`；数量采用相同过滤条件。type 不采用固定三项的 CHECK，便于后续扩展；当前手动入口仍固定赋值 manual。内容、时间及日归属校验由数据服务执行，不仅依赖界面。

#### 回收站状态与查询

回收站使用 logs.is_deleted，不增加日志时间字段或额外回收站表。软删除属于系统修改：设置 is_deleted=1，并自动将 updated_at 更新为真实操作时刻。回收站不允许编辑正文或记录时间，因此其 updated_at 同时表示本次移入回收站的时刻，用于展示及倒序排列。

```sql
CREATE INDEX idx_logs_trash_updated
  ON logs (updated_at DESC, id ASC)
  WHERE is_deleted = 1;
```

回收站查询使用 `WHERE is_deleted = 1 ORDER BY updated_at DESC, id ASC`。恢复设置 is_deleted=0 并更新 updated_at，保留 recordedAt、createdAt、type 与正文。再次软删除时记录新的真实 updatedAt，按最新移入时间排列。

彻底删除使用 ID 与 is_deleted=1 双条件，只允许删除回收站记录。编辑只作用于正常 manual 日志。状态不符或重复的请求不能虚报成功；所有修改失败时保持原数据库状态。

#### app_settings：应用偏好

| 字段       | 类型    | 约束与含义                                   |
| ---------- | ------- | -------------------------------------------- |
| key        | TEXT    | 主键，稳定设置键，不随界面语言变化           |
| value_json | TEXT    | 必填，合法 JSON 编码的设置值；由偏好服务校验 |
| updated_at | INTEGER | 最近成功写入时刻，UTC Unix 毫秒              |

```sql
CREATE TABLE app_settings (
  key TEXT NOT NULL PRIMARY KEY,
  value_json TEXT NOT NULL,
  updated_at INTEGER NOT NULL
);
```

首版键为 `themeMode` 与 `localePreference`，取值及默认行为见第 7.3 节。无语言偏好时不写该键；主题可使用缺省 `system`。

#### schema_migrations：数据库迁移记录

| 字段       | 类型    | 约束与含义                         |
| ---------- | ------- | ---------------------------------- |
| version    | INTEGER | 主键，递增正整数；首次结构版本为 1 |
| applied_at | INTEGER | 该迁移成功完成时刻                 |

```sql
CREATE TABLE schema_migrations (
  version INTEGER NOT NULL PRIMARY KEY CHECK (version > 0),
  applied_at INTEGER NOT NULL
);
```

- 建表与对应迁移记录在同一事务中完成；失败回滚，不将未完成版本标为已应用。
- 后续变更通过有序迁移完成，不删除数据库重新初始化。数据库版本高于应用支持范围时停止写入并提示，不强行降级。
- 本项目当前无正式业务数据；若研发中已有旧结构，则迁移缺少的 type 为 manual；旧 recordedAt 优先取原 occurred_at，其次 sent_at，最后 created_at。旧 deleted_at 非空时设置 is_deleted=1，并以该软删除操作时刻作为 updated_at；为空时设置 is_deleted=0。迁移完成后移除旧 sent_at、sent_time_zone、occurred_at、deleted_at 列，不保留两套业务时间字段。

### 7.2 标签与搜索的扩展边界

- 未来明确需要标签与搜索，但本版不实现、不显示入口，也不创建无实际功能的按钮或菜单。
- 允许在技术设计中保留统一的记录查询边界与可扩展的查询参数，明确未来可增加关键词与标签筛选；当前只提供日期和删除状态查询。
- 记录使用稳定 ID，便于未来建立标签关系与搜索索引；不提前创建标签表、全文索引、空实现或假返回结果。
- 若预留接口类型，本版调用方不得调用未实现能力；也不向界面暴露可用的搜索或标签 IPC 接口。
- 未来标签关系、搜索索引随版本迁移加入，并明确排除软删除记录的默认搜索规则；彻底删除时同步清理关联数据。

### 7.3 应用偏好数据

偏好与记录正文独立管理，存放于 `app_settings`，不增加到每条记录上：

| 设置             | 取值                        | 规则                                                                 |
| ---------------- | --------------------------- | -------------------------------------------------------------------- |
| themeMode        | `light` / `dark` / `system` | 默认 `system`；存用户模式，不存解析后的临时主题                      |
| localePreference | `en` / `zh-CN` / 未设置     | 未设置时按系统语言匹配，手动选择后持久化；结构支持未来注册的语言代码 |

偏好读取失败时使用默认值并提示，不影响已保存记录读取；写入失败不修改原已保存值。升级保留合法偏好，未知主题回退跟随系统，当前不支持的语言回退英文但保留原偏好以便后续兼容。语言资源是随应用分发的界面资源，不作为用户记录或草稿保存到数据库。

### 7.4 后续模块日志的数据边界

本版落地公共 `type` 字段与统一日志模型，不建立 todo 表、日程表或 APP 监测表。未来关联模块对象、事件细分与结构化载荷可通过数据库迁移和接口扩展加入；不能仅靠正文推断事件或反向控制原模块。本版纯文本正文与 10,000 字符限制针对手动记录，未来结构化载荷格式与限制另行定义。

### 7.5 新建提交一致性

- 输入正文、目标日期、时间模式和指定记录时间仅存于渲染层内存。
- 提交时生成稳定日志 ID 并固定 recordedAt 与 timeZone，直接写入 SQLite。
- 失败后保留本次提交信息，重试使用同一 ID；服务端按 ID 去重。
- 正式保存成功后清空输入；窗口关闭后不恢复未提交内容。

### 7.6 数据访问边界

启动先初始化数据库并读取偏好，再加载今天的日志并定位列表底部。数据库初始化失败时禁止提交。

正式日志、偏好与迁移由 Electron 主进程的数据服务管理；渲染层通过受控接口访问，不直接执行 SQL。SQL 使用参数绑定。当前接口覆盖手动日志创建、按日读取、编辑、软删除、回收站读取、恢复、彻底删除、偏好；未来模块接入接口另行设计，本版不实现。

SQLite 驱动在开发时选定，不影响本节表结构。
